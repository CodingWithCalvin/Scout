# Saved-evidence fast-workflow benchmark

This isolated developer experiment leaves application SQLite data and media unchanged. `prepare.py` reads all current Victorious saved dialogue, groups normalized identical transcripts, retains original filenames where known, and freezes a fixture. It uses TF-IDF cosine retrieval (five episodes) plus filename numbering/title hints. Reference labels and saved model conclusions never enter shortlisting. References with disagreement are unscored.

`run.py` reuses byte-equivalent saved Gemma results, runs Kev Q8_0 via the native System One endpoint for remaining dialogues, and applies fixed rules: support >= 0.61, margin >= 0.15, only one supported candidate, no filename disagreement, no multipart filename hint, no explicit feature/podcast candidate, and no competing distinct recording for that episode. These rules are experimental, not calibrated acceptance guarantees. Ambiguity invokes the current .NET DialogueMatcher with Gemma thinking and the full catalog. Raw responses are not manually edited. Final competing assignments are held. Compound Gemma coverage is held pending production multipart resolution.

Build `Scout.FastBenchmark.csproj` in Release first, then run prepare.py and run.py from the repository. These scripts use local fixture/model locations for this experiment; they are not dependencies of the shipped .NET application. Results/checkpoints live in `.build/fast-victorious`: pipeline.db, fixture.db, kev/decision.db and fallback/fallback.db. Only benchmark input and report artifacts are written outside those databases. Restarting run.py reuses completed Kev/Gemma checkpoints. Never rerun prepare.py over an active benchmark.

Many saved recordings lack consistent reference labels. Report separately: measured inference time, fallback demand, cached reuse, reference agreement/disagreement, errors, held conflicts and unscored assignments. Do not report agreement as independent accuracy or projected full-series timing as measured timing.
